# TerraSmart Destek

TerraSmart's RustDesk build for the VERA tablets. It is RustDesk with a few changes, kept as
small as possible so every upstream release can be followed:

| Change | Where |
|---|---|
| Package `tr.com.terrasmart.rustdesk`, name "TerraSmart Destek" (installs next to the field's `com.carriez.flutter_hbb`, whose signing key is lost) | `flutter/android/app/build.gradle`, `AndroidManifest.xml` |
| versionCode = upstream code × 100 + TerraSmart revision | `flutter/android/app/build.gradle` |
| `rustdesk.terrasmart.com.tr` and its key built in; update check and scam warning fixed off; floating window off by default (no "display over other apps" permission) | `libs/hbb_common` → `terrasmarttechnology/hbb_common`, branch `terrasmart-<version>` |
| Preset permanent password from the secret `TERRASMART_RUSTDESK_PASSWORD` (the build gets only `"00" + base64(sha256(password + salt))`; a password set on a tablet still wins) | `libs/hbb_common` (`HARD_SETTINGS`), `make-android-workflow.py` |
| The app writes its RustDesk ID into the Headwind device's `custom1` field (launcher plugin API `setCustom`), where the panel reads it | `TerraSmartMdm.kt`, `MainActivity.kt`, `flutter/lib/models/server_model.dart` (`fetchID`), `AndroidManifest.xml` (`<queries>`) |
| Android-only build signed with `terrasmart-rustdesk.jks`: one universal APK for arm64-v8a and armeabi-v7a, no per-ABI APKs | `.github/workflows/terrasmart-android.yml`, generated by `make-android-workflow.py` |

Updates reach the tablets only through Headwind (panel › Sürümler), never from the app itself.

## Building

Actions › **TerraSmart Destek Android** › Run workflow (branch `terrasmart`, revision `0`, or 1, 2,
… for a TerraSmart fix on the same upstream version). It stops if the signing secrets are missing,
checks every APK carries the certificate `b86ff2fa…2dec37`, and publishes the release
`destek-<version>-r<revision>`. It then uploads `rustdesk-<version>-universal-signed.apk` to
Headwind MDM as "TerraSmart Destek" and sets it to install in the configuration given as
`headwind_configuration` (default `VERA Development`; empty skips Headwind). That needs the
secrets `HEADWIND_MDM_URL`, `HEADWIND_LOGIN` and `HEADWIND_PASSWORD` (terrasmart-vera-android
keeps the same values as `HEADWIND_MDM_URL`, `HEADWIND_MDM_USERNAME`, `HEADWIND_MDM_PASSWORD`).

Only these two workflows run here. The ones inherited from upstream (CI, Full Flutter CI,
Flutter Tag Build, Fdroid, Nightly, …) are disabled in Actions; GitHub turns Actions off on
forks whose inherited workflows waste compute.

## Moving to a new RustDesk release

The **TerraSmart Destek upstream watch** workflow checks every morning. When RustDesk has
released a version the `terrasmart` branch is not on, it runs `terrasmart/move-to-upstream.sh`:
our hbb_common commits are replayed on the hbb_common commit the release uses, our commits here
on the release tag, `libs/hbb_common` points at the result, the workflow is regenerated, and
both are pushed as `terrasmart-<version>`. It then builds that branch (revision 0) and installs
it on VERA Development through Headwind, and opens an issue saying so. When a commit does not
apply, it builds nothing and the issue shows where it stopped.

This needs the secret `TERRASMART_BOT_TOKEN`: a fine-grained token for `terrasmarttechnology`
with Contents, Workflows and Actions read/write on `rustdesk` and `hbb_common`. The workflow's
own token cannot push to hbb_common, push workflow changes, or tag a commit whose workflows
differ from the default branch's, so the release step uses it too.

Once the build works on the VERA Development tablets:

```sh
git push -f origin terrasmart-$NEW:terrasmart
```

and run the build on `terrasmart` with the next revision and `headwind_configuration`
`VERA Staging` or `VERA Production`. By hand, the move is the same script; it stops with exit
status 2 and a message when a commit needs fixing:

```sh
terrasmart/move-to-upstream.sh 1.5.1 --no-push   # look at terrasmart-1.5.1, then push it
```
